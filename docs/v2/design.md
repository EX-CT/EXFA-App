# EXFA v2 设计方案（前端大升级 + 引擎/格式配套）

> 目标：横屏电脑单屏工作台，所有操作原地完成；引擎、格式、存储一次设计到位，web 与未来桌面端共用。
> 标 **【待定 Qn】** 的地方需要你拍板，其余是我的决定（你不同意可以直接改）。

---

## 一、品牌

- 图标包全部用上：`exfa.ico`/`exfa-32.png` 做 favicon，`180` 做 Apple Touch，`192/512` 做 PWA（网站可"安装"成独立窗口，打开像桌面软件），`1024`/`icns` 留给未来桌面端。
- 顶栏左侧放 logo + "EXFA"，About 页放大图。
- 配色从 logo 取：近黑暖底（#020000 / #180300 一系）+ 金色强调（logo 的金）。**【待定 Q1】** 红色怎么用。
- 字体缩小到 12px，行高收紧；数字一律等宽数字（tabular-nums），列才能对齐。

## 二、单屏布局（1920×1080 为基准，**【待定 Q2】**）

```
┌顶栏：logo │ 配置名/船 │ 角色 │ 伤害模型 │ 场景(假想敌) │ 操作模式[智能|替换|添加] │ 状态条┐
├────────左 300px────────┬──────────中 自适应──────────┬────右 340px────┤
│ 市场树（紧凑）          │ 配置行（Pyfa 式多列）        │ 解算数据（密）  │
│  搜索 + 类别筛选        │  高/中/低/改装/子系统        │ 资源条          │
│  图标16px·名·meta·槽位  │  无人机/舰载机/植入/货柜     │ 输出/防御/电容  │
│ ────────────           │ ───────────────────          │ 导航/锁定       │
│ 配置库（文件夹树）      │ 【原地对比条】选中模块的      │ 场景有效 dps    │
│  可折叠，和市场上下分    │  变种/替换候选 before→after  │ 问题/调整提示   │
│ ────────────           │ ───────────────────          │                │
│ 物品信息栏（已有）      │ 【图表坞】可折叠、可拉高      │                │
└────────────────────────┴──────────────────────────────┴────────────────┘
```

- 没有任何"点开变成另一页"：图表、对比、假设分析、配置库都是常驻面板，只能折叠/拉伸，不跳页。
- 原生 alert/confirm 全部删除。反馈分四级、四种样式：
  - **错误**（引擎失败）：红色行内条，出现在出错的位置；
  - **违规**（超 CPU、超舰载机管……游戏里装不上）：资源条/模块行红框 + 右栏"问题"；
  - **提醒**（技能缺失、未知投影等真问题）：黄色小条；
  - **自动调整**（引擎帮你纠正的输入）：灰色小字"已自动调整 3 项"，悬停看明细，不打扰；
  - 操作回执（"已替换 3 门炮，Ctrl+Z 撤销"）：右下角轻提示，2 秒消失。
- 市场树紧凑化：缩进 10px→8px，图标 20→16px，去掉单独的"类别"宽列（改成名字后的小标签，只在搜索结果里显示），meta 等级右对齐成一列，名字过长用省略号+悬停全名；一屏能看到的行数大约翻倍。

## 三、装备操作模式（核心交互）

顶栏三档，快捷键 `Q/W/E` 切换（输入框里不生效）：

| 模式 | 市场点击物品时 |
|---|---|
| **智能**（默认 **【待定 Q4】**） | 已选中一个模块且新物品能装同一类槽位 → 替换；否则添加到第一个空位 |
| **替换** | 永远替换选中模块（编组则整组替换）；槽位不同→行内提示"槽位不同，无法替换" |
| **添加** | 永远添加，不碰选中模块 |

- 选中模块：单击模块行（行高亮金边）；再点一次取消。弹药同理：选中武器后点市场弹药 = 换弹。
- 点击语义 **【待定 Q3】**：悬停市场物品就在"原地对比条"显示预览，单击即应用（全部可 Ctrl+Z）。
- 跨功能替换（扰断换推子/反跳）时，对比条第一列永远是 **CPU / PG / 电容** 的 before→after，超限直接红框；后面跟该功能相关指标。

## 四、变种选择 + 原地假设分析

- 选中模块后，配置区下方的"原地对比条"自动列出：该模块的全部变种（T1/T2/势力/死亡/官员/压缩），以及当前市场悬停的物品。
- 每行：`图标 名称 | CPU 30→38 (+8) | PG | 电容 | 关键指标1 | 关键指标2 | 关键指标3 | 价格 | [应用]`
- 关键指标按模块功能自动挑（你可以手动钉住）：
  - 推进：最高速度、起跑时间、信号半径、电容
  - 武器：dps、最佳+失准、追踪、对当前场景有效 dps
  - 坦克：EHP、主动坦克/s、抗性
  - 电战：强度、射程
  - 其他：用 What-if 的通用 8 项
- 颜色：绿=变好、红字=变差、灰=不变；**红框=应用后会违规**（超 CPU/PG 等），黄框=技能不够。
- 每个变种都是引擎真算一遍（一次批量调用，几十个变种也是毫秒级），不是估算。
- 现有的 What-if 大页面拆掉，功能并入对比条（离线贡献、换弹药、换角色作为对比条的页签）。

## 五、引擎：通用"预检/归一"层（v1.4.6 的升级版）

把"计算前自动纠正"变成正式机制，响应里四个列表各司其职：

| 字段 | 含义 | 例子 |
|---|---|---|
| `adjustments[]`（新） | 引擎替你纠正了输入，计算照常 | 被动件 active→online；铁骑数量钳到中队上限；同槽植入体去重；缺战术模式补默认；旧格式字段迁移；未知安全等级→nullsec；弹药不兼容→卸下 |
| `violations[]` | 输入合法但游戏里装不上 | 超 CPU/PG/校准、槽位/炮台不够、舰载机管/仓超限、限装一个 |
| `warnings[]` | 输入里有引擎无法处理的东西 | 技能缺失、未知 buff、不支持的投影 |
| `error` | 计算失败 | 船 id 不存在 |

- 每条 adjustment 带 `code / path / from / to`，前端据此做灰色小提示，也能"一键写回"把配置本身改正确（比如导入的 fit 里状态全被纠正了，点一下就把存档也改好）。
- `type` RPC 的 `allowed_states` 扩展成完整"编辑约束"：合法状态、可装弹药、槽位、限装数、中队上限——前端编辑时直接用，根本发不出坏请求。

## 六、自有通用格式：EXFA Fit Document（不是 EFT）

**【待定 Q6】** 放哪里。我的建议是单独开库 `EX-CT/EXFA-Format`，内含：JSON Schema（唯一权威）+ Rust crate（引擎/格式转换/未来桌面端用）+ TypeScript 类型包（前端用）+ 版本迁移函数 + 测试样例。

分三层，层层包含：

1. **Fit**（单个配置，可直接交给引擎算）：船、模块（type_id、槽位、状态、弹药、突变、spool、编组）、无人机、舰载机、植入体、增效剂、货柜、模式、角色引用、选项。全部用 type_id，名字只作可读注释。带 `sde: {build, dataset_rev}`，旧 SDE 的配置能识别出"这个物品已被删除/改名"。
2. **Fit Document**（用户保存的一份配置）：Fit + 名称、备注、标签 + **可替代件**（任意模块/弹药/无人机位置挂一组候选，像 Vexor 的 `==`，但结构化）+ **分支**（命名的一套候选选择，如"主线/低技能/省钱"）+ 版本历史。
3. **Library**（整个配置库）：文件夹树 + Fit Documents + 角色 + 伤害模型 + **场景** + **编队**。

- 外部格式（EFT/DNA/ESI/Pyfa XML/eftcfg/多买单）全部只在格式层出入：`EFT → Fit`、`Fit → EFT`。前端和引擎内部只认 Fit。前端现有的 TypeScript 版 EFT/DNA 解析器删除，全走 wasm（见第九节）。
- 引擎的 FitRequest 就是 Fit 层本身（加计算选项），不再是两套结构。
- 版本：`format: "exfa/1"`，每次结构变化写迁移函数，老文件永远能打开。

## 七、场景（假想敌）与图表

- 新增 **Scenario**（场景）对象，存在 Library 里，可复用、可导出：
  - 目标：引用一个目标模型（抗性/信号/速度/半径）或引用库里另一个配置；
  - 几何：距离、目标速度、目标方向角、我方速度、我方方向角（引擎早就支持角度，只是界面没露出来）；
  - 开关：是否用自己的网子/标记、是否忽略抗性、无人机跟随模式。
- **"固定一个敌人一个方向一个速度一个距离的有效 dps"不放在图表里**：引擎计算请求加 `scenarios[]`，响应返回每个场景的有效 dps/volley/命中率。右栏常驻显示"对场景 X 有效 dps"，MCP/AI 也通过同一个字段拿结果——一个逻辑，三处复用（界面、图表、AI）。
- **图表 = 场景的扫描**：选一个参数当横轴（距离、时间、目标速度/百分比、目标信号/百分比、目标方向角、我方速度、我方方向角、角速度），其余参数取自场景。新增"方向角/角速度"横轴需要引擎小改。
- **多条线 = 配置 × 场景 的组合**：可以勾选多个配置、多个假想敌，每个组合一条线；颜色区分配置、线型区分假想敌。引擎批量算点，前端负责叠加画图、图例、悬停读数、导出 PNG/CSV。
- 前端那套"估算版图表公式"删除（引擎永远在 wasm 里，没必要再估算）。

## 八、配置库：文件夹 + 可替代 + 编队关系

- 文件夹树任意层级，拖拽移动；左栏配置库常驻（和市场上下分屏）。
- 每个配置内的可替代件和分支（见第六节），界面上就是模块行右侧一个小 `⇄2` 徽标，点开在对比条里切换。**【待定 Q5】**
- **编队（Fleet Group）**：库里一种特殊文件夹，成员带角色：
  - "指挥"：它的指挥脉冲影响组内其他配置；
  - "成员"：受影响者；
  - "目标/友方"：可被投射（遥修、电战）。
  任意配置右键"设为本组指挥"即可。
- **引擎依旧单进单出**：前端（文档层）在发请求时把引用展开——指挥配置内联进 `fleet.booster_fits`，投射配置内联进 `projected`。引擎保持无状态、不知道有"库"这回事；桌面端/MCP 用同一个展开函数（放在格式库里），行为一致。

## 九、WASM 专注 + 启动速度 + 数据是否并入引擎

- **网页端删掉 HTTP 引擎选项**，只走 wasm；HTTP/stdio 服务继续保留给 MCP/API（引擎仓库不动）。
- 当前下载量：引擎 wasm 5.4 MB + 格式 wasm 2.9 MB（延迟加载）+ 界面数据集 1.3 MB。SDE 数据在三处各存一份。
- 方案：**合并成一个 `exfa.wasm`**（计算 + 格式转换 + 元数据），SDE 只存一份；界面需要的市场树/中英名称/搜索索引由引擎一次性生成交给前端（你提到的"装备数据融入引擎"），并缓存在 IndexedDB。最终用不用这条路我会**实测体积和首屏时间**再定：只有比现状更小更快才切换，否则保留数据集文件。
- 启动优化：wasm 流式编译 + 浏览器缓存（PWA Service Worker），二次打开秒开；界面骨架和本地配置库先渲染，引擎就绪后自动出数；数据集/wasm 按版本号缓存，只在发版时重下。

## 十、存储、导出、同步、桌面端

- 浏览器里：IndexedDB 存 Library（已有，升级为新格式，自动迁移旧数据，旧数据保留备份）。
- 导出：单个配置 `.exfa.json`、整个文件夹/全库 `.exfa-lib.zip`（文件夹结构原样保留）；仍可导出 EFT/DNA 等给别的工具。
- **【待定 Q7】** 同步方式。
- 桌面端：配置库在磁盘上就是"一个文件夹 = 一个文件夹，一个配置 = 一个 `.exfa.json`"，和网页端导出的结构完全相同，所以未来桌面端（Tauri，直接复用 Rust 引擎）开箱即读。**【待定 Q8】**
